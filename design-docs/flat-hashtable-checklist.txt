Flat hash table work plan (2026-09-19)

Scope: runtime table, ownership API, full normal-return correctness proof,
SIMD foundation, and installed-compiler benchmarks in one PR.

Design
- Unique keys, power-of-two capacity, triangular probing in 16-byte groups.
- Scanned interleaved key/value backing array and byte controls, with 15
  wraparound clones. Empty=128, Deleted=254, fingerprints=0..127.
- Check matching candidates before terminating on Empty. Occupancy includes
  live entries and tombstones and stays at or below 7/8 capacity.
- Rebuild at the same capacity with >=capacity/8 tombstones; otherwise double.
- Aliased handles, erased views, and one unique ghost token owning one or
  more heterogeneous tables. A table's private region includes its header
  and both backing blocks. Rebuilding preserves handle identity.
- Both keys and payloads currently require immutable_data. Hash/equality are
  pure total functions, with explicit equality/hash laws. Stateful callbacks
  and disjoint-frame lending await proper borrowing.

Proof boundary
The actual imperative algorithm is checked against typed C storage contracts.
The public operations establish normal-return functional correctness and exact
ownership/frame preservation. Probe coverage and vacancy non-exhaustion are
proved. General termination, allocation success and absence of capacity-limit
exceptions are not claimed. Migration retries with a larger destination on an
incomplete copy; no theorem says the first selected destination always suffices.

The trusted boundary includes C storage, exact SIMD/scalar matching, the Vox
checker/SMT solver and the existing finite-map heap laws. Heap.put_law adds
standard write-back identity when the value already occupies the location.
No assume_ or whole-table correctness axiom is introduced. SIMD differential
tests are not a machine-code proof. SSE2 is implemented but not run on this
arm64 machine.

Vox findings
- Mixed Int/BitVec reasoning made bounded bitclear decrease time out. Bitwise
  queries now use machine-width bitvectors consistently, including comparisons
  and datatype fields. Integer-only queries retain the existing encoding.
- Irrelevant SSA definitions inflated individual proof retries. Dependency
  slicing removes unused definitions without strengthening premises.
- Heap observation expansion had a shared budget across obligations. Suppress
  duplicate propagation and regenerate observations for individual retries.
  A 48-write regression checks valid reads and rejection of a false read.
- Slicing initially pruned lengths needed by latent array observations. Follow
  observation definitions during dependency collection. Expand explicit heap
  observations before slicing the initial batch; early slicing is restricted
  to individual retries. Existing raw_memory_demo covers explicit hints.
  The existing complete
  iarray_borrow test checks the affected array slicing lemmas.
- Result-only polymorphic definition lemmas can lose phantom type connections.
  Use explicit polymorphic signatures and a type-carrying model/entry argument.
  A locally abstract alternative encountered Ctype.Unify and is not used.
  Follow-up reproducers confirm the result-only type-instantiation limitation;
  a small locally abstract example reports a scope error rather than crashing.
  The original crash has not been reproduced or claimed fixed.
- Alias investigation: actual module aliases preserve predicate identity,
  including through inferred functor results. Separate functor applications
  have distinct values; their definition lemmas establish the connection.
  Regression examples cover both. Proof functors keep explicit invariant
  parameters to avoid repeatedly rebuilding these connections.
- Refined structural-recursion parameters now retain the inductive status of
  their payload. Descendant recursion is accepted; unchanged-root recursion
  remains rejected.
- A boxed all-void result is rejected. Mutations use unboxed records carrying
  erased views and ghost tokens; creation also carries the runtime handle.
- Standard raise and raise_notrace now have layout-polymorphic results.
  Resize uses standard raise for its erased unboxed result. Ordinary failwith
  and invalid_arg retain their existing value_or_null signatures.
- String literals now have consistent logical identities and distinct byte
  contents are provably unequal. Physical equality remains unknown. The table
  client proves a stored string is returned, across GC and compaction.
- For-loop bodies now receive inclusive bounds in both directions. Body facts
  do not escape the loop. Mask tests no longer need redundant bounds guards.

Benchmark: verification/benchmarks/flat_hashtbl_results.csv records five runs
per workload using the installed optimized arm64 compiler (-O3), shuffled
integer keys, and integer/string payloads. Base v0.17.3 is rebuilt with the
same compiler and hash function. Reproduce with:
  python3 verification/benchmarks/flat_hashtbl.py --prepare-base /tmp/vox-base \
    --build-dir /tmp/vox-flat --repeats 5 --implementations stdlib simd base
At 1,048,576 integer entries, median Base/flat ratios are 1.87x build,
2.18x hit, 3.46x miss, 2.13x replacement and 1.98x churn. Median flat times
are 78.66, 22.76, 9.22, 30.25 and 47.72 ns/op respectively. These five runs
use work factor 10, matching build sinks and precomputed replacement values.
Tiny builds/churn remain slower than Base and Stdlib. At 57,344 entries
(7/8 occupancy), misses take 18.88 ns vs Base's 13.40 ns. These results do
not establish performance for string keys or AMD64. String rows use integer
keys with string payloads. Find/mem allocate zero bytes. Churn can grow the
table; it is not a steady-state dense-table measurement.
Native lookup emits direct storage loads, SIMD comparisons, and hardware CTZ,
with no calls to C storage-read or control-match helpers. Allocation and
pointer-slot mutation still use runtime helpers. SIMD has a scalar C fallback;
the scalar ablation removes matching builtins from both interface and source.
The full table proof, native/bytecode stress tests, exhaustive control masks,
ownership rejection, and solver regressions pass.

- Review found linear bytecode stack consumption during migration. Carry the
  original heap as a ghost loop parameter and discharge frame composition
  before recursion, making the call structurally tail-recursive even with -g.
  The client fills and reads 65,536 entries with a bounded bytecode stack.

Follow-up experiments: first group, combined insertion, small tables
(2026-09-20; no algorithm changes retained)

- First-group peeling passed the full table proof and native/bytecode tests.
  It caused the specialized comparator to become out of line again and
  regressed hits/replacement. Restored the prior search implementation.
- Combined insertion checked each group's candidates before selecting a
  vacancy. A tombstone was remembered while the existing search continuation
  ruled out a later duplicate; empty termination established absence. The
  saved route witness was ghost, and rebuild discarded the saved vacancy.
  Full table proofs and bytecode/native runtime tests passed.
- Tested unboxed index/byte returns, explicit first-insertion-probe inlining,
  a single encoded runtime index with ghost byte/route, capacity-16 fallback,
  and explicit replacement inlining. Each benchmark compilation checked the
  complete library refinements. The strongest compromise (replace-inline)
  improved build/replacement/churn at 64-1,024 entries by about 5-11%, but
  slowed replacement at 1-8 entries by 11-13% and dense 57,344-entry misses
  by about 8%. Rejected instead of trading away the across-sizes objective.
  Its library patch is /tmp/vox-table-next/encoded-insertion.patch.
- A policy preferring an empty slot without first looking for tombstones
  avoided one control comparison, but substantially regressed churn. Rejected.
- Paired data: verification/benchmarks/flat_hashtbl_followup_results.csv.
  Each row summarizes six pairs, work factor 20, both payloads, seven sizes.
  Integer keys throughout; string payloads are not string keys. The fused
  run used fixed baseline-first order; later two-variant runs alternated.
  Raw runs and binaries: /tmp/vox-table-next/. Benchmarks used the installed
  optimized compiler without concurrent builds or reviews. Reported ranges
  are observed paired ratios, not confidence intervals. Unchanged lookup
  source also changed measured dense misses: generated-code layout and
  specialization remain relevant, and the exact cause is not established.
- Separately measured a benchmark-only, unverified eight-slot dense-array
  prototype with integer and actual string keys, against Stdlib, at 1/2/4/8
  entries. Five runs used precomputed keys and separately allocated equal
  strings for hits. String keys had a common prefix. At 1 entry, hits were
  1.89/1.99 ns (dense/Stdlib, int), 3.98/11.01 ns (string). At 8 entries,
  misses were 7.44/1.58 ns (int), 22.13/11.91 ns (string). No promotion path
  or correctness proof was implemented for this prototype. These fixed-order
  microbenchmarks do not compare against the verified SIMD table or establish
  a universal small-table policy. Source/data: /tmp/vox-table-next/small.ml,
  /tmp/vox-table-next/small.csv. A generic eight-entry linear mode was not
  adopted. A single allocation containing SIMD controls and entries remains
  unevaluated and would require a separate storage/promotion proof.
- Retained a deterministic test: fill across multiple probe groups, delete
  in the first group, replace a later-group key without increasing length,
  then insert an absent key and verify that the tombstone is reused.
- Final ./dev test vox/table_model.ml passes bytecode/native proofs and runtime
  checks. codex review --uncommitted completed with no actionable findings.
- Vox issue observed: placing the new test before the existing two-table
  pointer ownership test caused a refinement counterexample at pointer_fill
  alias 0 first.view other.state. Appending the identical test after existing
  tests passed. No ownership contract or proof was weakened. Declaration-order
  sensitivity remains unexplained and merits a minimized compiler reproducer.
