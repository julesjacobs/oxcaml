vox is an experimental extension of the OxCaml compiler in which types carry refinements, as in the examples below. Refinements become proof obligations, discharged at compile time by Lean 4’s grind or manually proven lemmas (or checked at runtime with assume_); a failed obligation is a compile error with a counterexample. Verification is opt-in per function.

How it works

  • Refinements are Lean propositions; anything provable in Lean can be a refinement.
  • Refinements can mention the variables in scope, function arguments included (dependent types); a program variable in a refinement denotes its logical Lean counterpart.
  • Refinements generalize pre/postconditions: they attach to any type, and the typechecker propagates them through data structures and polymorphic functions.
  • OCaml functions can be used in specs: marking a function total_ reflects it into the logic, and refinements can then call it.
  • Specs go on module signatures: an .mli can state a model and prove its theorems; both travel in the .cmi, and clients verify against the interface.
  • Automation: grind handles the common case; missed goals are proved with tactics next to the code and registered with @[grind]; everything is kernel-checked.
  • Failures produce counterexamples: the goal, the hypotheses in scope, and a violating input, at the offending expression.
  • Unique mutation using the mode system: RustHorn-style mutable borrows (see the parallel in-place quicksort demo).
  • Specs work as tests: reflected predicates are executable OCaml, usable as runtime checks (assume_) and as oracles for property-based testing, fuzzing, and AI-driven bug finding.

Refinement types, by example

The first example proves that appending two lists adds their lengths. The specification needs a length function it can mention, so the setup is a list type and the usual recursive definition of length:

type ilist =
  | Nil
  | Cons of int * ilist

(* total_ reflects len into the logic, so the refinements below can
   call it; Lean checks it terminates. *)
let rec total_ len l =
  match l with
  | Nil -> 0
  | Cons (_, t) -> 1 + len t

The total_ keyword reflects len into the logic: the compiler emits it as a Lean def, Lean checks that it terminates, and refinements can then call it. Only total_ functions can be reflected: a partial function has no logical counterpart (from f x = f x + 1 the logic would conclude 0 = 1).

(* Proved: each recursive call is the induction hypothesis. *)
let rec append (a : ilist) (b : ilist) : ilist{ len _ = len a + len b } =
  match a with
  | Nil -> b
  | Cons (h, t) ->
    let r = append t b in
    Cons (h, r)

Apart from the annotation on its result type, append is ordinary OCaml, and it compiles to the same code. The expression between braces is a term of the logic, written in OCaml syntax. It may mention the program variables in scope, including the function’s own parameters; _ denotes the value the refinement is attached to, in this case the result of append. In the logic, a program variable stands for the logical counterpart of its run-time value: an int corresponds to a mathematical integer, a variant such as ilist to the corresponding Lean inductive value, and values of other types to opaque atoms.

A refinement on the result is a postcondition, which the body must establish in every arm. The Nil arm follows from the definition of len. In the Cons arm, the recursive call has the same signature, instantiated at t and b, so len r = len t + len b is known; this is the induction hypothesis. The compiler emits each obligation as a Lean theorem, and Lean’s grind proves it automatically; the file contains no proof text.

(* The bounds are a contract, discharged at every call site. *)
let rec nth (l : ilist) (i : int{ 0 <= _ && _ < len l }) : int =
  match l with
  | Nil -> unreachable_   (* must be proved: [false] from the facts here *)
  | Cons (h, t) -> if i = 0 then h else nth t (i - 1)

A refinement on a parameter is a precondition: every caller must prove it, and the body may assume it. Within the body, branch conditions are also in scope, so the recursive call discharges its bounds from i <> 0 and the Cons match. The Nil arm is dead code given the bounds; unreachable_ makes this a proof obligation (the goal false under the arm’s hypotheses) where assert false would defer it to run time. Proof obligations arise in exactly three ways: applications of functions with refined parameters, refine_ e claims, and unreachable_.

Refinements generalize pre- and postconditions. A refinement can also appear under a type constructor: int{ _ >= 0 } list states that every element is nonnegative. Because the fact is part of the type, the typechecker propagates it, and polymorphic functions preserve it by instantiation: List.rev at 'a = int{ _ >= 0 } returns nonnegative elements with nothing to prove (in effect, unary parametricity).

Specs on module signatures

An .mli can state a model and prove its theorems once, in an embedded Lean block; definitions and theorems travel in the .cmi, so clients verify against the interface without reading the implementation, and editing a spec changes the checksum, which forces clients to re-verify. The BST below is built this way; the trie that follows applies the same shape to harder code.

bst.mli states the model (whole-tree membership, the ordering invariant, a model-level insert); the implementation is checked against it arm by arm. The one-path search is proved equal to membership over the whole tree, and each insert arm is proved to build exactly the model’s tree, with no proof text and no trust keyword.

type tree =
  | Leaf
  | Node of tree * int * tree

type set = tree{ bst _ }

let empty : set{ _ = Leaf } = Leaf

let rec member (x : int) (t : set) : bool{ _ = mem x t } =
  match t with
  | Leaf -> false
  | Node (l, v, r) ->
    if x = v then true
    else if x < v then member x l
    else member x r

let rec insert (x : int) (t : set) : set{ _ = insert x t && mem x _ }
  =
  match t with
  | Leaf -> Node (Leaf, x, Leaf)
  | Node (l, v, r) ->
    if x = v then t
    else if x < v then begin
      let l' = insert x l in
      Node (l', v, r)
    end
    else begin
      let r' = insert x r in

The Patricia trie

This is the integer-set structure OxCaml’s optimizer uses (middle_end/flambda2/algorithms/patricia_tree.ml), in its classic little-endian form: the GADT plumbing stripped, the bit twiddling kept, including i land b = 0, i land (b - 1), and the lowest-set-bit trick x land (-x) that appears verbatim in the compiler’s unpack. The interface models the bit operations arithmetically and proves the bit-level facts from first principles in core Lean, so nothing about bits is axiomatized. The trust surface is three one-line bridges (vox does not reflect the bitwise operators), each carrying its arithmetic model as its contract. From there the Patricia invariant, the one-path search, and insertion are proved arm by arm against the model.

type t =
  | Empty
  | Leaf of int
  | Branch of int * int * t * t

type set = t{ trie _ }

let zero_bit (i : int) (b : int{ isbit _ }) : bool{ _ = zbit i b } =
  assume_unchecked_ (i land b = 0)

let mask (i : int) (b : int{ isbit _ }) : int{ _ = mask i b } =
  assume_unchecked_ (i land (b - 1))

let branching_bit (p0 : int) (p1 : int{ _ <> p0 }) : int{ _ = bbit p0 p1 } =
  assume_unchecked_ (let x = p0 lxor p1 in x land (-x))

(* Split two subtrees with distinct prefixes at their branching bit,
   zero side left.  The result is proved to be the model's [join];
   note [mask]'s precondition is discharged by [bbit_isbit]. *)
let join (p0 : int) (t0 : t) (p1 : int{ _ <> p0 }) (t1 : t)
  : t{ _ = join p0 t0 p1 t1 } =
  let b = branching_bit p0 p1 in
  let p = mask p0 b in
  let z = zero_bit p0 b in
  if z then Branch (p, b, t0, t1) else Branch (p, b, t1, t0)

let empty : set{ _ = Empty } = Empty

(* One path decides membership in the whole tree: a failed prefix
   test proves the key is in NEITHER subtree, and the branching bit
   proves it is not in the sibling we skip. *)
let rec mem (i : int) (s : set) : bool{ _ = mem i s } =
  match s with
  | Empty -> false
  | Leaf j -> i = j
  | Branch (p, b, t0, t1) ->
    let m = mask i b in
    if m <> p then false
    else begin
      let z = zero_bit i b in
      if z then mem i t0 else mem i t1
    end

let rec insert (i : int) (s : set) : set{ _ = insert i s && mem i _ } =
  match s with
  | Empty -> Leaf i
  | Leaf j ->
    if i = j then s
    else begin
      let l = Leaf i in
      join i l j s
    end
  | Branch (p, b, t0, t1) ->
    let m = mask i b in
    if m = p then begin
      let z = zero_bit i b in
      if z then begin
        let t0' = insert i t0 in
        Branch (p, b, t0', t1)
      end
      else begin
        let t1' = insert i t1 in
        Branch (p, b, t0, t1')
      end
    end
    else begin
      let l = Leaf i in
      join i l p s
    end

type t =

  | Leaf of int

[%%vox.lean {lean|
-- Bit-level theory.  [mask i b] keeps the bits of [i] strictly below
-- the power-of-two bit [b]; [zbit i b] says bit [b] of [i] is clear.
-- Euclidean / and % are floor semantics for positive divisors, i.e.
-- exactly infinite two's complement.
def mask (i b : Int) : Int := i % b

def zbit (i b : Int) : Prop := i % (2*b) < b

instance (i b : Int) : Decidable (zbit i b) := by unfold zbit; infer_instance

inductive isbit : Int -> Prop where
  | one : isbit 1
  | dbl : {b : Int} -> isbit b -> isbit (2*b)

-- Lowest differing bit of two distinct integers (junk 1 when equal).
def bbit (p0 p1 : Int) : Int :=
  if p0 = p1 then 1
  else if p0 % 2 = p1 % 2 then 2 * bbit (p0/2) (p1/2)
  else 1
termination_by (p0.natAbs + p1.natAbs)
decreasing_by omega

theorem isbit_pos {b : Int} (h : isbit b) : 1 ≤ b := by
  induction h <;> omega

-- The workhorse: peel one bit off a modulus.
theorem emod_unique {a b q r : Int} (h0 : 0 ≤ r) (h1 : r < b)
    (h : a = b*q + r) : a % b = r := by
  subst h
  rw [Int.add_comm, Int.add_mul_emod_self_left]
  exact Int.emod_eq_of_lt h0 h1

theorem emod_double (p m : Int) (hm : 0 < m) :
    p % (2*m) = 2 * ((p/2) % m) + p % 2 := by
  have h2 := Int.mul_ediv_add_emod p 2
  have h3 := Int.mul_ediv_add_emod (p/2) m
  have h4 := Int.emod_nonneg (p/2) (show m ≠ 0 by omega)
  have h5 := Int.emod_lt_of_pos (p/2) hm
  have h6 := Int.emod_nonneg p (show (2:Int) ≠ 0 by omega)
  have h7 := Int.emod_lt_of_pos p (show (0:Int) < 2 by omega)
  apply emod_unique (q := (p/2)/m) (by omega) (by omega)
  calc p = 2 * (m * ((p/2)/m) + (p/2) % m) + p % 2 := by rw [h3]; omega

theorem bbit_lt (p0 p1 : Int) :

theorem isbit_dvd {b : Int} (hb : isbit b) :
    ∀ a, isbit a → a ≤ b → a ∣ b := by
  induction hb with
  | one =>
    intro a ha hle
    have := isbit_pos ha
    have : a = 1 := by omega
    subst this; exact Int.one_dvd 1
  | @dbl c hc ih =>
    intro a ha hle
    cases ha with
    | one => exact Int.one_dvd _
    | @dbl a' ha' =>
      have := ih a' ha' (by omega)
      rcases this with ⟨k, hk⟩
      exact ⟨k, by rw [hk, Int.mul_assoc]⟩

-- Tree model: naive membership over the WHOLE tree, and the Patricia
-- invariant -- at every branch on bit [b] with prefix [p], all keys
-- match [p] below [b], the zero side has bit [b] clear, the one side
-- has it set.
@[grind] def mem : Int -> Vox_Ptrie_t -> Prop
  | _, .Empty => False
  | i, .Leaf j => i = j
  | i, .Branch _ _ t0 t1 => mem i t0 ∨ mem i t1

@[grind] def allmatch : Vox_Ptrie_t -> Int -> Int -> Prop
  | .Empty, _, _ => True
  | .Leaf j, p, b => mask j b = p
  | .Branch _ _ t0 t1, p, b => allmatch t0 p b ∧ allmatch t1 p b

@[grind] def allzero : Vox_Ptrie_t -> Int -> Prop
  | .Empty, _ => True
  | .Leaf j, b => zbit j b
  | .Branch _ _ t0 t1, b => allzero t0 b ∧ allzero t1 b

@[grind] def allone : Vox_Ptrie_t -> Int -> Prop
  | .Empty, _ => True
  | .Leaf j, b => ¬ zbit j b
  | .Branch _ _ t0 t1, b => allone t0 b ∧ allone t1 b

@[grind] def trie : Vox_Ptrie_t -> Prop
  | .Empty => True
  | .Leaf _ => True
  | .Branch p b t0 t1 =>
      isbit b ∧ mask p b = p ∧
      allmatch t0 p b ∧ allmatch t1 p b ∧
      allzero t0 b ∧ allone t1 b ∧ trie t0 ∧ trie t1

@[grind] def join (p0 : Int) (t0 : Vox_Ptrie_t) (p1 : Int) (t1 : Vox_Ptrie_t) :
    Vox_Ptrie_t :=
  if zbit p0 (bbit p0 p1)
  then .Branch (mask p0 (bbit p0 p1)) (bbit p0 p1) t0 t1
  else .Branch (mask p0 (bbit p0 p1)) (bbit p0 p1) t1 t0

@[grind] def insert (i : Int) : Vox_Ptrie_t -> Vox_Ptrie_t
  | .Empty => .Leaf i
  | .Leaf j => if i = j then .Leaf i else join i (.Leaf i) j (.Leaf j)
  | .Branch p b t0 t1 =>
      if mask i b = p then
        if zbit i b then .Branch p b (insert i t0) t1
        else .Branch p b t0 (insert i t1)
      else join i (.Leaf i) p (.Branch p b t0 t1)

(* The API type is the refined abbreviation: a set IS a tree
   satisfying the Patricia invariant. *)
type set = t{ trie _ }

val empty : set{ _ = Empty }

(* One-path search, proved equal to the model membership that
   quantifies the WHOLE tree: the invariant's lemmas bridge the path
   the code takes to the subtrees it skips. *)
val mem : (i : int) -> (s : set) -> bool{ _ = mem i s }

(* Insertion returns exactly the model's insert; [mem_insert] then
   characterizes the result completely at every client. *)
val insert : (i : int) -> (s : set) -> set{ _ = insert i s && mem i _ }

The full-fidelity variant (lib/ptrie_packed) is big-endian like the compiler, with the prefix and the branching bit packed into one int per branch exactly as the compiler's prefix_and_bit packs them: pack is lor, and unpack recovers the bit with x land (-x). The invariant rides the packed int: for a well-formed node the bit is its lowest set bit and the prefix is the rest, as theorems (lbit_pack) rather than fields. A hand-built node's packed int is therefore checked: mis-pack it and the invariant refuses, with the decode in the counterexample.

Automation

grind covers the same ground as an SMT solver (congruence closure, E-matching, linear arithmetic), so the common case feels like SMT-backed refinement types. When it misses, the fix is a lemma stated next to the code and proved with tactics (work language models are now good at), then registered with the automation via @[grind], so the push-button case gets stronger over time for that codebase. Lean’s lemma libraries (mathlib) live in the same logic; the developments on this page prove everything from core Lean. grind produces proof terms that Lean’s kernel checks, so the automation itself is outside the trust surface.

Three implementations in one file: the naive recursion, reflected, is the specification; a tail-recursive loop carries its invariant in the parameter contracts; and O(log n) fast doubling is verified against the same fib. (* Tail-recursive accumulator loop, O(n) iterations: the parameters
   carry the invariant (a, b) = (fib i, fib (i+1)) with i >= 0 as
   CONTRACTS -- the body assumes them, and each call site discharges
   them at its own (bare) arguments, the shifted accumulators and the
   literal seeds included.  (For n < i the loop diverges; partial
   correctness is unbothered.)  The recursive call is the bare tail:
   its result refinement [_ = fib n] is the enclosing one, so it
   passes through with no obligation at all. *)
let rec fib_loop (n : int) (i : int) (a : int{ _ = fib i && i >= 0 })
  (b : int{ _ = fib (i + 1) }) : int{ _ = fib n }
  =
  if i = n
  then a
  else begin
    fib_loop n (i + 1) b (a + b)
  end

let fib_iter (n : int) : int{ _ = fib n } = fib_loop n 0 0 1

(* Fast doubling, O(log n) iterations, on NATIVE pairs
   (fib n, fib (n+1)) -- tuples appear in predicates directly.  With
   k = n/2: fib (2k) = fib k * (2 fib (k+1) - fib k) and fib (2k+1) =
   fib k ^ 2 + fib (k+1) ^ 2 (the embedded lemmas; they need k >= 0,
   hence the precondition on n, discharged at each call).  The
   midpoint is reflected T-division; its parity annotation is PROVED
   (grind derives the disjunction from the tdiv bounds).  Annotating
   x and y with the doubling identities puts [fib (2 * k)]
   syntactically in each obligation, which is what fires the lemmas;
   the final obligations are then pure congruence. *)
let rec fib_fd (n : int{ _ >= 0 }) : (int * int){ _ = (fib n, fib (n + 1)) } =
  if n <= 0
  then (0, 1)
  else begin
    let k : int{ n = 2 * _ || n = 2 * _ + 1 } = n / 2 in
    let q = fib_fd k in
    match q with
    | (a, b) ->
      let x : int{ _ = fib (2 * k) } = a * (2 * b - a) in
      let y : int{ _ = fib (2 * k + 1) } = a * a + b * b in
      if n = 2 * k
      then (x, y)
      else (y, x + y)
  end

Unique mutation

OxCaml’s mode system was built for allocation control, but it provides the ownership substrate a verifier needs: a unique value has no other references (what justifies a strong update), once makes capability tokens affine, and local confines a value to its region. vox added no checker machinery: the mode checker enforces the ownership discipline, refinements carry the ghost state, and a small trusted library (accounted for in the trust table below) encodes the heap logic on top. Rust’s verifiers (Creusot, Prusti, RustHorn) make the analogous move on the borrow checker.

The smallest case, a mutable borrow (demo/lean_borrow.ml): the loan’s final value is a prophecy variable p, the borrower proves an export in lender terms, and after resolution the lender reads the residual back with proof. Double use, forged exports, and writes through frozen loans are compile-time errors.

let bump : (a : int) -> int{ _ = a + 1 } =
  fun a ->
  let x = vnew a in
  let p = new_proph () in
  let (x', u) = borrow_mut p x (fun m ->
    let (r, m1) = mget m in              (* r = now m = x = a *)
    let m2 = mset m1 (r + 1) in
    let _u0 = mdrop m2 in         (* fin m2 = now m2 *)
    (() : unit{ p = a + 1 }))    (* export in lender terms *)
  in
  ignore u;                              (* u carried p = a + 1 *)
  let s = vpeek x' in                    (* s = x' = p *)
  s

Verified sorted-and-permutation on a borrowed slice, with the fork-join parallel version under the same spec. @ unique says the loan has no other references (what justifies mutating in place), @ local confines it to its region, and now m / fin m are a RustHorn-style borrow’s current and final (prophesied) contents. Specs as tests

A contract is written once, independent of how it is enforced. Today the mechanisms are proof and runtime checking (assume_ compiles the predicate into a test); since reflected specifications are executable OCaml, the same contract can also serve as the oracle for property-based testing, fuzzing, or AI-driven input search. None of these exist in vox yet; they would consume the specs unchanged. Inductive invariants (a tree staying ordered under every insertion) are facts that sampling cannot confirm.

Dropping runtime checks

get reads with Iarray.unsafe_get, so there is no bounds check in the compiled code; its contract demands the proof at every call site instead. The loop below discharges it from the loop bound and the path fact. Nothing about any index is assumed:

let sum : (a : int iarray) -> int =
  fun a ->
    let n = Iarray.length a in
    let rec go : (i : int{ 0 <= _ && _ <= n }) -> int -> int =
      fun i acc -> if i < n then go (i + 1) (acc + Ia_lib.unsafe_get a i) else acc
    in
    go 0 0

The benchmark (docs/vox/bench) compiles this kernel natively, under verification; the benchmark driver itself does not compile until it proves its arrays compatible. Measured on a dev box, the verified dot product runs 1.36× the bounds-checked loop, and the verified sum matches hand-written unsafe_get. The same reasoning applies to other checks that exist only because a known fact was never stated: validation on trusted paths, defensive re-checks across module boundaries, option-wrapping of values that cannot be absent.

A tree flipped in place demo/lean_flip.ml

A mutable tree with a pure ghost model: flip swaps child pointers in place, its dependent signature model _ = mirror (model h) makes each recursive call the induction hypothesis, and flipping twice is provably the identity.

let rec flip : (h : vtree) @ unique -> vtree{ model _ = mirror (model h) } @ unique =
  fun h ->
  let (b, h1) = is_node h in
  if b
  then (
    let (l, k) = take_left h1 in
    let l' = flip l in
    let h2 = put_left k l' in
    let (r, k2) = take_right h2 in
    let r' = flip r in
    let h3 = put_right k2 r' in
    let h4 = swap_kids h3 in
    h4)
  else h1

let roundtrip : (t : tree) -> tree{ _ = t } =
  fun t ->
  let h = of_pure t in
  let h1 = flip h in
  let h2 = flip h1 in
  let r = to_pure h2 in
  r

A separation logic demo/lean_sep.ml

One unique token owns the heap; its refinement carries a reified assertion, and the frame is an explicit parameter. Reads recover the ghost values, writes rewrite the points-to chunks, and two live references are distinct because Star means disjoint.

let swap :
  (r1 : href) -> (r2 : href) -> (a : int) -> (b : int) -> (p : hprop) ->

  htoken{ sat (Star (Pts (r1, b), Star (Pts (r2, a), p))) (hp _) } @ unique =
  fun r1 r2 a b p t ->
  let f1 = Star (Pts (r2, b), p) in
  let (x, t) = get r1 a f1 t in
  let f2 = Star (Pts (r1, a), p) in
  let (y, t) = get r2 b f2 t in
  let t = set r1 a y f1 t in
  let f3 = Star (Pts (r1, y), p) in
  let t = set r2 b x f3 t in
  ignore x; ignore y;
  t

Integer square root demo/lean_isqrt.ml

Integer square root against a reflected sq: the result is bracketed by squares of the same function the program runs. The midpoint is reflected division; one nonlinear lemma is proved in an embedded block. Nothing in the file is assumed, and returning the wrong endpoint is caught with a concrete counterexample (x = 0).

let total_ sq m = m * m

let isqrt (x : int{ 0 <= _ }) : {r:int | 0 <= r && sq r <= x && x < sq (r + 1)} =
  let rec go (lo : int{ 0 <= _ && sq _ <= x })
    (hi : int{ lo < _ && x < sq _ })
    : {r:int | 0 <= r && sq r <= x && x < sq (r + 1)}
    =
    if lo + 1 < hi
    then begin
      let m = (lo + hi) / 2 in
      if sq m <= x then go m hi else go lo m
    end
    else lo
  in
  go 0 (x + 1)

Mutable locals, loop invariants demo/lean_mutable.ml

Reads of a let mutable variable name its current SSA version; every write mints a fresh one. A [@vox.invariant] formula follows the classical quadruple — asserted at entry, assumed at the loop head, asserted again at the back-edge — and may mention a for-loop’s index; after the loop it stands at one past the end.

let iota : (n : int) -> {r:int | (n < 1 && r = 0) || (n >= 1 && r = n)} =
  fun n ->
  let mutable x = 0 in
  (for i = 1 to n do
     x <- x + 1
   done) [@vox.invariant x = i - 1];
  refine_ x

Binary search, imperative demo/lean_imp_binsearch.ml

The recursive bracket invariant of lower_bound, worn as a loop annotation: two unrefined mutable indices, plain reads and writes, and the flip-point postcondition falls out of the invariant together with the negated guard.

let search2
  : (a : int iarray) -> (x : int)
    -> bracket{ _.hi = _.lo + 1
                && -1 <= _.lo && _.hi <= Iarray.length a
                && (0 <= _.lo -> a.(_.lo) < x)
                && (_.hi < Iarray.length a -> a.(_.hi) >= x) }
  =
  fun a x ->
  let n = Iarray.length a in
  let mutable lo = -1 in
  let mutable hi = n in
  (while hi - lo > 1 do
     let l = lo in
     let h = hi in
     let mid = (l + h) / 2 in
     let v = Ia_lib.get a mid in
     if v >= x then hi <- mid else lo <- mid
   done)
  [@vox.invariant
    -1 <= lo && lo < hi && hi <= Iarray.length a
    && (lo = -1 || Iarray.get a lo < x)
    && (hi = Iarray.length a || Iarray.get a hi >= x)];
  let l = lo in
  let h = hi in
  { lo = l; hi = h }

Reflected arithmetic Vox_reflect

+ - * / mod, comparisons, and && || not carry their logical meaning, recognized by primitive rather than by name (a shadowed (+) is not addition). Division is OCaml’s T-division, totalized soundly under partial correctness. A branch condition contributes itself as a fact: writing if n <= 0 is enough.

Costs and trust

What a claim on this page is worth depends on what is proved, what is checked at runtime, and what is assumed:

ConstructStatusNotes
refine_ eProved Emitted as a Lean theorem; failure is a compile error with goal, hypotheses, and model.
parameter contractsProved Discharged at every application, at the argument’s logical name.
total_ definitionsDefinitional The emitted Lean def is the OCaml body; Lean independently checks termination.
[%%vox.lean] theoremsProved Hand-written lemmas are Lean-checked on every compile; a false proof is a compile error.
assume_ eRuntime-checked The compiler inserts the test; a violated assumption raises rather than entering the logic. Compiled only when the check is faithful to the logic; otherwise a compile error.
assume_unchecked_ e, axiom in blocksTrusted The primary trust surface. In the Patricia trie it is three bit-twiddling one-liners.
[@@vox.sort] ghost sorts; library mode castsTrusted The mutation encodings’ trust surface: ghost types declaring their logical sort, and the Obj.magic-family casts inside the token, borrow, slice, and separation-logic libraries (about 450 lines in all). The audit grep is assume_unchecked_ + Obj.magic + [@@vox.sort] over the trusted libs.

Verification runs inside ocamlc: a typical verified module in the suite adds about one second of Lean per compile; heavier inductive developments (the trie, quicksort) cost more. Obligations are re-proved on every build, so there is no stale-proof state, and editing a spec changes the .cmi checksum, which forces clients to re-verify. The compiler footprint is about 4,900 lines in typing/ plus changes to arrows and unification; the build gains a pinned Lean toolchain.

A broken obligation goes red at that function, like a type error, but closing a hard goal can require writing Lean, and grind can fail on goals that are true (nonlinear arithmetic, quantifier instantiation). The options, in order: prove a lemma in an embedded block, downgrade to a runtime-checked assume_, or leave the function unannotated. Known limits: partial correctness (termination is checked only for total_ definitions), ideal integers (no overflow model), no shared-state concurrency beyond mode-checked disjointness, and client axioms in lemma blocks join the trust surface silently today (a lint is planned).

Each feature shipped with adversarial probes (forged tokens, duplicated loans, escaped borrows, prophecy reuse, false exports), each pinned in the test suite to the layer that rejects it. The Lean itself was mostly agent-drafted against grind’s counterexample feedback; provenance does not matter for soundness, since Lean re-checks everything on every build.

Directions

Everything above is CI-checked today, on unmodified OxCaml modes and a stock Lean. Next, roughly in order:

  • Verified hot-path kernels behind plain interfaces, with their defensive checks deleted.
  • Interface models for core containers and protocol layers, so client code proves against them without reading implementations.
  • Concurrency beyond fork-join disjointness: an invariant layer for shared state.
  • Spec-driven testing at the assume_ boundary: quickcheck-style generators, fuzzers, AI-driven input search.
  • Confining the trust surface to designated modules, so a library’s claims hold for downstream users by construction.
