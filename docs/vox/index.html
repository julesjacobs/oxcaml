Refinement types for OxCaml,
discharged by Lean at compile time.

vox is an experimental extension of the OxCaml compiler. Types may carry logical predicates; the resulting proof obligations are sent to Lean 4's grind on every ocamlc invocation, and an undischarged obligation is a compile error.

The program is its own spec A function marked total_ becomes a logical function; its OCaml body is the definition the solver reasons from.
Re-checked on every build Obligations are emitted as Lean theorems and re-proved from scratch each compile. Solver timeout or error fails the build.
Failures include a model A failed obligation reports its goal, the hypotheses in scope, and the candidate counterexample the solver ended on.
Specs cross module boundaries Reflected definitions and lemma blocks travel in the .cmi; clients verify against them directly.

The model, briefly

A refinement is a predicate on a type: int{ _ >= 0 }, int{ not (_ = 0) }. A refinement on a parameter is a contract: the body assumes it, and each call site must discharge it. Here the branch condition is sufficient, and the check is fully automatic:

let div : (a : int) -> (b : int{ not (_ = 0) }) -> int = fun a b -> a / b

let safe x = if 0 < x then div 100 x else 0

Proof obligations arise from exactly two places: applications to refined parameters, as above — no annotation at the call — and explicit refine_ e claims (a result refinement, a stored value). Both are proved. Trust is explicit and graded: assume_ e is checked at runtime (the compiler inserts the test), and assume_unchecked_ e is trusted outright — the one escape hatch, and it is greppable.

Reflected functions: total_

Marking a recursive function total_ translates its body into the logic. The compiler emits it as an ordinary Lean def, Lean checks termination, and the function's name becomes usable inside refinements. The inductive proof about append below requires no solver-side definitions and no proof text:

let rec total_ len l =
  match l with
  | Nil -> 0
  | Cons (_, t) -> 1 + len t

(* The textbook inductive proof, against the REFLECTED len: no prelude
   measure.  Each recursive call re-instantiates the dependent
   signature -- the induction hypothesis, unpacked by the [let] that
   names it; grind unfolds [len] via the definitional equations. *)
let rec append : (a : ilist) -> (b : ilist) -> ilist{ len _ = len a + len b } =
  fun a b ->
    match a with
    | Nil -> b
    | Cons (h, t) ->
      let r = append t b in
      Cons (h, r)

Each recursive call re-instantiates the declared signature at its actual arguments, which is the induction hypothesis. Non-structural recursion carries a metric — [@@vox.decreases n] — from which the termination argument is synthesized.

A complete development in one file

Three Fibonacci implementations: the naive recursion, reflected, is the specification; a tail-recursive accumulator loop carries its invariant in the parameter contracts; and O(log n) fast doubling is verified against the same fib. The doubling identities are proved in an embedded Lean block, by functional induction on the reflected definition itself — there is no second, solver-side Fibonacci. The one assumption is the halving primitive (asr is outside the logic), and it is runtime-checked.

    fib (m + n + 1) = fib (m + 1) * fib (n + 1) + fib m * fib n := by
  fun_induction fib m with
  | case1 x h => grind
  | case2 x => grind
  | case3 x h1 h2 ih1 ih2 =>
    have i1 := ih1 (by omega)
    have i2 := ih2 (by omega)
    have e1 : x - 1 + n + 1 = x + n := by omega
    have e2 : x - 2 + n + 1 = x + n - 1 := by omega
    have e3 : x - 1 + 1 = x := by omega
    have e4 : x - 2 + 1 = x - 1 := by omega

    have e5 : x + n + 1 - 1 = x + n := by omega

    have e8 : x + 1 - 2 = x - 1 := by omega

(* A reflected call names itself: the program's fib meets the spec
   definitionally (the goal is [fib n = fib n]). *)
let fib_slow : (n : int) -> int{ _ = fib n } = fun n -> fib n

(* Tail-recursive accumulator loop, O(n) iterations: the parameters
   carry the invariant (a, b) = (fib i, fib (i+1)) with i >= 0 as
   CONTRACTS -- the body assumes them, and each call site discharges
   them at its own (bare) arguments, the shifted accumulators and the
   literal seeds included.  (For n < i the loop diverges; partial
   correctness is unbothered.)  The recursive call is the bare tail:
   its result refinement [_ = fib n] is the enclosing one, so it
   passes through with no obligation at all. *)
let rec fib_loop
  : (n : int) -> (i : int) -> (a : int{ _ = fib i && i >= 0 })
    -> (b : int{ _ = fib (i + 1) }) -> int{ _ = fib n }
  =
  fun n i a b ->
    if i = n
    then a
    else begin
      fib_loop n (i + 1) b (a + b)
    end

let fib_iter : (n : int) -> int{ _ = fib n } =
  fun n -> fib_loop n 0 0 1

(* Fast doubling, O(log n) iterations, on NATIVE pairs
   (fib n, fib (n+1)) -- tuples appear in predicates directly.  With
   k = n/2: fib (2k) = fib k * (2 fib (k+1) - fib k) and fib (2k+1) =
   fib k ^ 2 + fib (k+1) ^ 2 (the embedded lemmas; they need k >= 0,
   hence the precondition on n, discharged at each call).  The
   midpoint is reflected T-division; its parity annotation is PROVED
   (grind derives the disjunction from the tdiv bounds).  Annotating
   x and y with the doubling identities puts [fib (2 * k)]
   syntactically in each obligation, which is what fires the lemmas;
   the final obligations are then pure congruence. *)
let rec fib_fd : (n : int{ _ >= 0 }) -> (int * int){ _ = (fib n, fib (n + 1)) } =
  fun n ->
    if n <= 0
    then (0, 1)
    else begin
      let k : int{ n = 2 * _ || n = 2 * _ + 1 } = n / 2 in
      let q = fib_fd k in
      match q with
      | (a, b) ->
        let x : int{ _ = fib (2 * k) } = a * (2 * b - a) in
        let y : int{ _ = fib (2 * k + 1) } = a * a + b * b in
        if n = 2 * k
        then (x, y)
        else (y, x + y)
    end

(* Client side: fib 10, by fast doubling; the precondition [10 >= 0]
   is discharged at the literal argument. *)
let fib10 : int{ _ = fib 10 } =
  let r = fib_fd 10 in
  match r with
  | (u, _) -> u

The goal, the hypotheses in scope, and the arithmetic model the solver ended on, rewritten to source names. On linear goals the model is a genuine refutation; nonlinear atoms print as separate entries, so a model that is only linear-consistent is identifiable as such.

Algebraic data types demo/lean_adt.ml

Constructors of simple variants appear in predicates; a match refines its scrutinee; injectivity and distinctness come from the solver's datatype theory.   | Nil -> 0

Contracts as loop invariants demo/lean_fib.ml

Parameter refinements are preconditions, so a recursive function's parameters can carry its invariant — here (a, b) = (fib i, fib (i+1)). Call sites discharge it as ordinary obligations, including at the literal seeds in fib_loop n 0 0 1 and the compound arguments (i + 1), (a + b).

let rec fib_loop
  : (n : int) -> (i : int) -> (a : int{ _ = fib i && i >= 0 })
    -> (b : int{ _ = fib (i + 1) }) -> int{ _ = fib n }
  =
  fun n i a b ->
    if i = n
    then a
    else begin
      fib_loop n (i + 1) b (a + b)
    end

let fib_iter : (n : int) -> int{ _ = fib n } =
  fun n -> fib_loop n 0 0 1

Reflected arithmetic Vox_reflect

+ - * / mod, comparisons, and && || not carry their logical meaning, recognized by primitive rather than by name (a shadowed (+) is not addition). Division is OCaml's T-division, totalized soundly under partial correctness. A branch condition contributes itself as a fact: writing if n <= 0 is enough.

A verified module behind an interface

The shape that scales. bst.mli states the model — whole-tree membership, the ordering invariant, a model-level insert — and proves its theorems once, in the interface's embedded block; definitions and theorems travel in the .cmi. The implementation is checked against them arm by arm: the efficient one-path search is proved equal to membership over the whole tree (the ordering lemmas account for the subtrees the code never visits), and each insert arm is proved to build exactly the model's tree. Nothing is assumed, and no verification keyword appears in the code.

  | _, .Leaf => False

  | .Leaf, _ => True

  | .Leaf, _ => True
  | .Node l v r, b => v > b ∧ all_gt l b ∧ all_gt r b

@[grind] def bst : Vox_Bst_tree -> Prop
  | .Leaf => True
  | .Node l v r => all_lt l v ∧ all_gt r v ∧ bst l ∧ bst r

  | x, .Leaf => .Node .Leaf x .Leaf
  | x, .Node l v r =>
      if x = v then .Node l v r
      else if x < v then .Node (insert x l) v r
      else .Node l v (insert x r)

-- The ordering invariant makes one-path search complete: an element
-- bounded away from a subtree is not in it.
theorem not_mem_lt (x b : Int) (t : Vox_Bst_tree)
    (h : all_lt t b) (hx : b <= x) : ¬ mem x t := by
  induction t <;> grind
grind_pattern not_mem_lt => mem x t, all_lt t b

theorem not_mem_gt (x b : Int) (t : Vox_Bst_tree)
    (h : all_gt t b) (hx : x <= b) : ¬ mem x t := by
  induction t <;> grind
grind_pattern not_mem_gt => mem x t, all_gt t b

theorem all_lt_insert (x b : Int) (t : Vox_Bst_tree)
    (h : all_lt t b) (hx : x < b) : all_lt (insert x t) b := by
  induction t <;> grind

(* The API type is the refined abbreviation itself: a set IS a tree
   satisfying the ordering invariant.  Parameters of type [set] are
   contracts through the abbreviation like any other. *)
type set = tree{ bst _ }

val empty : set{ _ = Leaf }

(* Efficient one-path search, proved equal to the model membership
   (which quantifies the WHOLE tree): the ordering lemmas bridge the
   path the code takes to the subtrees it skips. *)
val member : (x : int) -> (t : set) -> bool{ _ = mem x t }

(* Insertion returns exactly the model's insert; the [set] layer and
   the equation conjoin (a refinement over a refined abbreviation
   FLATTENS onto the underlying skeleton), and [mem x _] plus the full
   characterization [mem y (insert x t) <-> y = x || mem y t] follow
   from the exported theorems. *)
val insert : (x : int) -> (t : set) -> set{ _ = insert x t && mem x _ }

let empty : set{ _ = Leaf } = Leaf

let rec member : (x : int) -> (t : set) -> bool{ _ = mem x t } =
  fun x t ->
    match t with
    | Leaf -> false
    | Node (l, v, r) ->
      if x = v then true
      else if x < v then member x l
      else member x r

let rec insert
  : (x : int) -> (t : set) -> set{ _ = insert x t && mem x _ }
  =
  fun x t ->
    match t with
    | Leaf -> Node (Leaf, x, Leaf)
    | Node (l, v, r) ->
      if x = v then t
      else if x < v then begin
        let l' = insert x l in
        Node (l', v, r)
      end
      else begin
        let r' = insert x r in
        Node (l, v, r')
      end
let demo : bool{ _ } * bool{ not _ } =
  let e = empty in
  let t1 = insert 2 e in
  let t2 = insert 1 t1 in
  let t3 = insert 3 t2 in
  let hit = member 2 t3 in
  let miss = member 5 t3 in
  (hit, miss)

The miss is as proved as the hits: mem_insert characterizes each insertion completely, down to mem 5 empty = False.

module Set : sig
  val add
    : (x : int) -> (t : set)
      -> set{ forall_ y. mem y _ = (y = x || mem y t) }
end = struct

let probe : (t : set) -> bool{ _ = mem 7 t } =
  fun t ->
    let t' = Set.add 2 t in
    let b = member 7 t' in
    b

With quantifiers in predicates (forall_/exists_), the exported theorem can live in the TYPE instead: an alternative interface over the untouched module states everything add does in one refinement, and a client instantiates it at whatever key it asks about.

Trust model

ConstructStatusNotes
refine_ eProved Emitted as a Lean theorem; failure is a compile error with goal, hypotheses, and model.
parameter contractsProved Discharged at every application, at the argument's logical name.
total_ definitionsDefinitional The emitted Lean def is the OCaml body; Lean independently checks termination.
assume_ eRuntime-checked The compiler inserts the test; a violated assumption raises rather than entering the logic. Compiled only when the check is faithful to the logic; otherwise a compile error.
assume_unchecked_ e, [%%vox.lean] blocksTrusted The explicit trust surface. In the fib development it amounts to one line: floor halving.

Known limits, by design: partial correctness (a diverging call neither proves nor asserts anything), and ideal integer arithmetic (overflow is outside the model). Both are documented in DESIGN.md.
