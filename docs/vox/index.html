Refinement types for OxCaml,
every obligation checked by Lean.

vox is an experimental extension of the OxCaml compiler: types may carry logical predicates, and the compiler discharges every resulting proof obligation through Lean 4's grind — at every ocamlc invocation. If it compiles, the properties hold.

The program is its own spec Mark a function total_ and its definition becomes a logical function — no hand-written solver definitions, no drift.
Really proved, every build Obligations become Lean theorems, re-established from scratch on each compile. Solver timeout or error is a compile error.
Failures carry counterexamples A failed obligation reports its goal, hypotheses, and a concrete candidate model: n = 0, fib n = 0.
Specs travel with modules Reflected definitions and lemma blocks ride the .cmi; clients verify against another module's functions directly.

vox in sixty seconds

A refinement is a predicate on a type: int{ _ >= 0 }, int{ not (_ = 0) }. A refinement on a parameter is a contract: callers prove it, the body assumes it. Here the branch condition is all the proof div's contract needs — and the compiler finds it:

let div : (a : int) -> (b : int{ not (_ = 0) }) -> int = fun a b -> a / b

let safe x = if 0 < x then div 100 x else 0

Three keywords control where obligations come from and where trust goes: refine_ e claims a refinement and is proved; assume_ e is checked at runtime (the compiler inserts the test); assume_unchecked_ e is trusted — the only escape hatch, and it is grep-able.

The program is the spec: total_

Marking a recursive function total_ reflects its definition into the logic: the compiler translates the body, emits it as an honest Lean def, and Lean checks termination. Calls of the function name themselves, and the same name can be applied inside any refinement. The textbook inductive proof about append then needs zero solver-side text:

let rec total_ len l =
  match l with
  | Nil -> 0
  | Cons (_, t) -> 1 + len t

(* The textbook inductive proof, against the REFLECTED len: no prelude
   measure.  Each recursive call re-instantiates the dependent
   signature (the induction hypothesis); grind unfolds [len] via the
   definitional equations. *)
let rec append : (a : ilist) -> (b : ilist) -> ilist{ len _ = len a + len b } =
  fun a b ->
    match a with
    | Nil -> refine_ b
    | Cons (h, t) ->
      let refine_ r = append t b in
      refine_ (Cons (h, r))

Each recursive call re-instantiates the declared signature at its actual arguments — the induction hypothesis, for free. Non-structural recursion carries a metric ([@@vox.decreases n]) from which the termination proof is synthesized.

A complete verified development in one file

Three Fibonacci implementations — the naive recursion (reflected: it is the spec), a tail-recursive accumulator loop whose invariant rides the parameter contracts, and O(log n) fast doubling — plus the doubling lemmas, proved by functional induction on the reflected definition itself, in an embedded Lean block next to the code. There is no second Fibonacci anywhere. The only trusted line is the halving primitive (asr is outside the logic), and even that is runtime-checked.

(* Demo: Fibonacci, where the spec IS the program, and the whole
   development is ONE FILE.  The naive recursion below is TOTAL
   (reflected): the compiler translates its definition into the logic
   and emits it as a Lean [@[grind] def], with [termination_by]
   synthesized from [@@vox.decreases n]; an applied [fib] in any
   refinement then denotes this very function.  The tail-recursive
   accumulator loop and the O(log n) fast doubling are verified
   against it.  Every obligation is really proved: a recursive call
   re-instantiates the dependent signature at the actual arguments, so
   its refined result is the induction hypothesis; the fast-doubling
   identities are lemmas in an embedded [%%vox.lean] block,
   proved by functional induction DIRECTLY on the reflected [fib] --
   there is no second, Lean-side Fibonacci anywhere.  The only assumed
   primitive is floor halving, whose [asr] the logic does not model --
   and even that assumption is RUNTIME CHECKED. *)

let half : (x : int) -> int{ x = 2 * _ || x = 2 * _ + 1 } =
  fun x -> assume_ (x asr 1)

let rec total_ fib n =
  if n <= 0
  then 0
  else if n = 1
  then 1
  else fib (n - 1) + fib (n - 2)
[@@vox.decreases n]

(* The fast-doubling identities, stated and proved about the reflected
   [fib] itself: the addition formula goes by [fun_induction fib] (the
   induction principle of the emitted definition), and the doubling
   identities are corollaries.  [@[grind =]] keys them on the
   [fib (2 * k)] / [fib (2 * k + 1)] goal terms that the annotations
   in [fib_fd] provide. *)
[%%vox.lean {lean|
theorem fib_rec (n : Int) (h : 2 <= n) : fib n = fib (n - 1) + fib (n - 2) := by
  grind

theorem fib_add (m n : Int) (hm : 0 <= m) (hn : 0 <= n) :
    fib (m + n + 1) = fib (m + 1) * fib (n + 1) + fib m * fib n := by
  fun_induction fib m with
  | case1 x h => grind
  | case2 x => grind
  | case3 x h1 h2 ih1 ih2 =>
    have i1 := ih1 (by omega)
    have i2 := ih2 (by omega)
    have e1 : x - 1 + n + 1 = x + n := by omega
    have e2 : x - 2 + n + 1 = x + n - 1 := by omega
    have e3 : x - 1 + 1 = x := by omega
    have e4 : x - 2 + 1 = x - 1 := by omega
    rw [e1, e3] at i1
    rw [e2, e4] at i2
    have u0 := fib_rec (x + n + 1) (by omega)
    have e5 : x + n + 1 - 1 = x + n := by omega
    have e6 : x + n + 1 - 2 = x + n - 1 := by omega
    rw [e5, e6] at u0
    have u1 := fib_rec (x + 1) (by omega)
    have e7 : x + 1 - 1 = x := by omega
    have e8 : x + 1 - 2 = x - 1 := by omega
    rw [e7, e8] at u1
    have u2 := fib_rec x (by omega)
    grind

  by_cases h0 : k = 0
  · subst h0; grind
  · have h := fib_add (k - 1) k (by omega) hk
    have e1 : k - 1 + k + 1 = 2 * k := by omega
    have e2 : k - 1 + 1 = k := by omega

    grind

  have e : k + k + 1 = 2 * k + 1 := by omega

(* A reflected call names itself: the program's fib meets the spec
   definitionally (the goal is [fib n = fib n]). *)
let fib_slow : (n : int) -> int{ _ = fib n } = fun n -> refine_ (fib n)

(* Tail-recursive accumulator loop, O(n) iterations: the parameters
   carry the invariant (a, b) = (fib i, fib (i+1)) with i >= 0 as
   CONTRACTS -- the body assumes them, and each call site discharges
   them at its own (bare) arguments, the shifted accumulators and the
   literal seeds included.  (For n < i the loop diverges; partial
   correctness is unbothered.) *)
let rec fib_loop
  : (n : int) -> (i : int) -> (a : int{ _ = fib i && i >= 0 })
    -> (b : int{ _ = fib (i + 1) }) -> int{ _ = fib n }
  =
  fun n i a b ->
    if i = n
    then refine_ a
    else begin
      let refine_ r = fib_loop n (i + 1) b (a + b) in
      refine_ r
    end

let fib_iter : (n : int) -> int{ _ = fib n } =
  fun n -> fib_loop n 0 0 1

(* Fast doubling, O(log n) iterations, on NATIVE pairs
   (fib n, fib (n+1)) -- tuples appear in predicates directly.  With
   k = n/2: fib (2k) = fib k * (2 fib (k+1) - fib k) and fib (2k+1) =
   fib k ^ 2 + fib (k+1) ^ 2 (the embedded lemmas; they need k >= 0,
   hence the precondition on n, discharged at each call).  Annotating
   x and y with the doubling identities puts [fib (2 * k)]
   syntactically in each obligation, which is what fires the lemmas;
   the final obligations are then pure congruence. *)
let rec fib_fd : (n : int{ _ >= 0 }) -> (int * int){ _ = (fib n, fib (n + 1)) } =
  fun n ->
    if n <= 0
    then refine_ (0, 1)
    else begin
      let refine_ k = half n in
      let refine_ q = fib_fd k in
      match q with
      | (a, b) ->
        let refine_ x = (refine_ (a * (2 * b - a)) : int{ _ = fib (2 * k) }) in
        let refine_ y = (refine_ (a * a + b * b) : int{ _ = fib (2 * k + 1) }) in
        if n = 2 * k
        then refine_ (x, y)
        else refine_ (y, x + y)
    end

(* Client side: fib 10, by fast doubling; the precondition [10 >= 0]
   is discharged at the literal argument. *)
let fib10 : int{ _ = fib 10 } =
  let refine_ r = fib_fd 10 in
  match r with
  | (u, _) -> refine_ u

When you're wrong, it tells you where — with a witness

let rec total_ fib n =
  if n <= 0 then 0 else if n = 1 then 1 else fib (n - 1) + fib (n - 2)
[@@vox.decreases n]

(* Off by one: fib is not n+1.  The compiler says so, with a witness. *)
let wrong : (n : int) -> int{ _ = fib n } = fun n -> refine_ (n + 1)
Error: vox: verification failed (lean).
       Goal: (n + 1) = (fib n)
Hypotheses: <none>
Possible counterexample:
  n = 0
  fib n = 0
(lean: error: `grind` failed)

The goal, the hypotheses in scope, and the model the solver's arithmetic ended on, rewritten to source names. On linear goals it is a genuine refutation; nonlinear atoms print as their own entries so a merely linear-consistent model is visibly so.

Feature tour

Algebraic data types demo/lean_adt.ml

Constructors of simple variants live in predicates; matches refine the scrutinee; injectivity and distinctness come from the solver's datatype theory. Note the Nil branch: it is unreachable, and the compiler proves it — the match facts contradict, so even 0 = 3 discharges.

let head (s : ilist{ _ = Cons (3, Nil) }) : {r:int | r = 3} =
  let refine_ s = s in
  match s with
  | Cons (h, _) -> refine_ h
  | Nil -> refine_ 0

Records & projections demo/lean_records.ml

Immutable records become Lean structures; field projection appears in predicates, and functional update gets the frame for free.

let origin : point{ _.px = 0 && _.py = 0 } = refine_ { px = 0; py = 0 }

let swap : (p : point) -> point{ _.px = p.py && _.py = p.px } =
  fun p -> refine_ { px = p.py; py = p.px }

Contracts: invariants on parameters demo/lean_fib.ml

Parameter refinements are preconditions. The loop below carries (a, b) = (fib i, fib (i+1)) in its types; every call site — including the literal seeds in fib_loop n 0 0 1 and the compound arguments (i + 1), (a + b) — discharges them as ordinary obligations.

Specs cross module boundaries demo/lean_reflectclient.ml

A total_ function's definition rides its unit's .cmi. Clients name it, apply it in predicates, and run inductive proofs against it — the .cmi checksum forces re-verification when the spec changes.

Interior mutability demo/lean_pcell.ml

Reflected arithmetic Vox_reflect

+ - * / mod, comparisons, and && || not carry their logical meaning (recognized by primitive, so shadowing cannot lie; division is OCaml's T-division, totalized soundly under partial correctness). Conditions contribute themselves as path facts: write if n <= 0 and the branch knows it.

The trust model, in one table

ConstructStatusNotes
refine_ eProved Becomes a Lean theorem; failure is a compile error with goal, hypotheses, counterexample.
parameter contractsProved Discharged at every application, at the argument's logical name.
total_ definitionsDefinitional The emitted Lean def is the body; Lean independently checks termination.
assume_ eRuntime-checked The compiler inserts the test; a violated assumption raises instead of corrupting the logic. Only compiled when the check is faithful; otherwise it is a compile error.
assume_unchecked_ e, [%%vox.lean] blocksTrusted The explicit, auditable trust surface. In the fib development it is one line: floor halving.

Documented caveats: partial correctness (a diverging call proves nothing, and asserts nothing), and ideal integer arithmetic (overflow is outside the model).
