Refinement types for OxCaml,
discharged by Lean at compile time.

vox is an experimental extension of the OxCaml compiler. Types may carry logical predicates; the resulting proof obligations are sent to Lean 4's grind on every ocamlc invocation, and an undischarged obligation is a compile error.

The program is its own spec A function marked total_ becomes a logical function; its OCaml body is the definition the solver reasons from.
Re-checked on every build Obligations are emitted as Lean theorems and re-proved from scratch each compile. Solver timeout or error fails the build.
Failures include a model A failed obligation reports its goal, the hypotheses in scope, and the candidate counterexample the solver ended on.
Specs cross module boundaries Reflected definitions and lemma blocks travel in the .cmi; clients verify against them directly.

The model, briefly

A refinement is a predicate on a type: int{ _ >= 0 }, int{ not (_ = 0) }. A refinement on a parameter is a contract: the body assumes it, and each call site must discharge it. Here the branch condition is sufficient, and the check is fully automatic:

let div : (a : int) -> (b : int{ not (_ = 0) }) -> int = fun a b -> a / b

let safe x = if 0 < x then div 100 x else 0

Proof obligations arise from exactly two places: applications to refined parameters, as above — no annotation at the call — and explicit refine_ e claims (a result refinement, a stored value). Both are proved. Trust is explicit and graded: assume_ e is checked at runtime (the compiler inserts the test), and assume_unchecked_ e is trusted outright — the one escape hatch, and it is greppable.

Reflected functions: total_

Marking a recursive function total_ translates its body into the logic. The compiler emits it as an ordinary Lean def, Lean checks termination, and the function's name becomes usable inside refinements. The inductive proof about append below requires no solver-side definitions and no proof text:

let rec total_ len l =
  match l with
  | Nil -> 0
  | Cons (_, t) -> 1 + len t

(* The textbook inductive proof, against the REFLECTED len: no prelude
   measure.  Each recursive call re-instantiates the dependent
   signature -- the induction hypothesis, unpacked by the [let] that
   names it; grind unfolds [len] via the definitional equations. *)
let rec append : (a : ilist) -> (b : ilist) -> ilist{ len _ = len a + len b } =
  fun a b ->
    match a with
    | Nil -> b
    | Cons (h, t) ->
      let r = append t b in
      Cons (h, r)

Each recursive call re-instantiates the declared signature at its actual arguments, which is the induction hypothesis. Non-structural recursion carries a metric — [@@vox.decreases n] — from which the termination argument is synthesized.

A complete development in one file

Three Fibonacci implementations: the naive recursion, reflected, is the specification; a tail-recursive accumulator loop carries its invariant in the parameter contracts; and O(log n) fast doubling is verified against the same fib. The doubling identities are proved in an embedded Lean block, by functional induction on the reflected definition itself — there is no second, solver-side Fibonacci. The one assumption is the halving primitive (asr is outside the logic), and it is runtime-checked.

   development is ONE FILE.  The naive recursion below is TOTAL
   (reflected): the compiler translates its definition into the logic
   and emits it as a Lean [@[grind] def], with [termination_by]
   synthesized from [@@vox.decreases n]; an applied [fib] in any
   refinement then denotes this very function.  The tail-recursive
   accumulator loop and the O(log n) fast doubling are verified
   against it.  Every obligation is really proved: a recursive call
   re-instantiates the dependent signature at the actual arguments, so
   its refined result is the induction hypothesis; the fast-doubling
   identities are lemmas in an embedded [%%vox.lean] block,
   proved by functional induction DIRECTLY on the reflected [fib] --
   there is no second, Lean-side Fibonacci anywhere.  NOTHING in this
   file is assumed: the midpoint is reflected T-division, and its
   parity annotation is PROVED. *)

let rec total_ fib n =
  if n <= 0
  then 0
  else if n = 1
  then 1
  else fib (n - 1) + fib (n - 2)
[@@vox.decreases n]

   [fib] itself: the addition formula goes by [fun_induction fib] (the
   induction principle of the emitted definition), and the doubling
   identities are corollaries.  [@[grind =]] keys them on the
   [fib (2 * k)] / [fib (2 * k + 1)] goal terms that the annotations

theorem fib_add (m n : Int) (hm : 0 <= m) (hn : 0 <= n) :
    fib (m + n + 1) = fib (m + 1) * fib (n + 1) + fib m * fib n := by
  fun_induction fib m with
  | case1 x h => grind
  | case2 x => grind
  | case3 x h1 h2 ih1 ih2 =>
    have i1 := ih1 (by omega)
    have i2 := ih2 (by omega)
    have e1 : x - 1 + n + 1 = x + n := by omega
    have e2 : x - 2 + n + 1 = x + n - 1 := by omega
    have e3 : x - 1 + 1 = x := by omega
    have e4 : x - 2 + 1 = x - 1 := by omega
    rw [e1, e3] at i1
    rw [e2, e4] at i2
    have u0 := fib_rec (x + n + 1) (by omega)
    have e5 : x + n + 1 - 1 = x + n := by omega
    have e6 : x + n + 1 - 2 = x + n - 1 := by omega
    rw [e5, e6] at u0
    have u1 := fib_rec (x + 1) (by omega)
    have e7 : x + 1 - 1 = x := by omega
    have e8 : x + 1 - 2 = x - 1 := by omega
    rw [e7, e8] at u1
    have u2 := fib_rec x (by omega)
    grind

(* A reflected call names itself: the program's fib meets the spec
   definitionally (the goal is [fib n = fib n]). *)
let fib_slow : (n : int) -> int{ _ = fib n } = fun n -> fib n

(* Tail-recursive accumulator loop, O(n) iterations: the parameters
   carry the invariant (a, b) = (fib i, fib (i+1)) with i >= 0 as
   CONTRACTS -- the body assumes them, and each call site discharges
   them at its own (bare) arguments, the shifted accumulators and the
   literal seeds included.  (For n < i the loop diverges; partial
   correctness is unbothered.)  The recursive call is the bare tail:
   its result refinement [_ = fib n] is the enclosing one, so it
   passes through with no obligation at all. *)
let rec fib_loop
  : (n : int) -> (i : int) -> (a : int{ _ = fib i && i >= 0 })
    -> (b : int{ _ = fib (i + 1) }) -> int{ _ = fib n }
  =
  fun n i a b ->
    if i = n
    then a
    else begin
      fib_loop n (i + 1) b (a + b)
    end

let fib_iter : (n : int) -> int{ _ = fib n } =
  fun n -> fib_loop n 0 0 1

(* Fast doubling, O(log n) iterations, on NATIVE pairs
   (fib n, fib (n+1)) -- tuples appear in predicates directly.  With
   k = n/2: fib (2k) = fib k * (2 fib (k+1) - fib k) and fib (2k+1) =
   fib k ^ 2 + fib (k+1) ^ 2 (the embedded lemmas; they need k >= 0,
   hence the precondition on n, discharged at each call).  The
   midpoint is reflected T-division; its parity annotation is PROVED
   (grind derives the disjunction from the tdiv bounds).  Annotating
   x and y with the doubling identities puts [fib (2 * k)]
   syntactically in each obligation, which is what fires the lemmas;
   the final obligations are then pure congruence. *)
let rec fib_fd : (n : int{ _ >= 0 }) -> (int * int){ _ = (fib n, fib (n + 1)) } =
  fun n ->
    if n <= 0
    then (0, 1)
    else begin
      let k : int{ n = 2 * _ || n = 2 * _ + 1 } = n / 2 in
      let q = fib_fd k in
      match q with
      | (a, b) ->
        let x : int{ _ = fib (2 * k) } = a * (2 * b - a) in
        let y : int{ _ = fib (2 * k + 1) } = a * a + b * b in
        if n = 2 * k
        then (x, y)
        else (y, x + y)
    end

(* Client side: fib 10, by fast doubling; the precondition [10 >= 0]
   is discharged at the literal argument. *)
let fib10 : int{ _ = fib 10 } =
  let r = fib_fd 10 in
  match r with
  | (u, _) -> u

What a failure looks like

let rec total_ fib n =
  if n <= 0 then 0 else if n = 1 then 1 else fib (n - 1) + fib (n - 2)
[@@vox.decreases n]

(* Off by one: fib is not n+1.  The compiler says so, with a witness. *)
let wrong : (n : int) -> int{ _ = fib n } = fun n -> refine_ (n + 1)
Error: vox: verification failed (lean).
       Goal: (n + 1) = (fib n)
Hypotheses: <none>
Possible counterexample:
  n = 0
  fib n = 0
(lean: error: `grind` failed)

The goal, the hypotheses in scope, and the arithmetic model the solver ended on, rewritten to source names. On linear goals the model is a genuine refutation; nonlinear atoms print as separate entries, so a model that is only linear-consistent is identifiable as such.

Features

Algebraic data types demo/lean_adt.ml

Constructors of simple variants appear in predicates; a match refines its scrutinee; injectivity and distinctness come from the solver's datatype theory. The Nil branch below is unreachable, and that is proved rather than assumed: its facts are contradictory, so the bare 0 discharges against r = 3.

let head (s : ilist{ _ = Cons (3, Nil) }) : {r:int | r = 3} =
  match s with
  | Cons (h, _) -> h
  | Nil -> 0

Records and projections demo/lean_records.ml

Immutable records become Lean structures. Field projection appears in predicates; functional update preserves the untouched fields' facts.

let origin : point{ _.px = 0 && _.py = 0 } = { px = 0; py = 0 }

let swap : (p : point) -> point{ _.px = p.py && _.py = p.px } =
  fun p -> { px = p.py; py = p.px }

Native tuples demo/lean_tuples.ml

Unlabeled tuples are structural: one polymorphic product per arity, so construction and fst/snd appear in predicates with no wrapper type and the predicate language stays untyped. Matching (or a destructuring let) contributes per-component facts, and tuples of int/bool compare with = in the logic.

let swap : (p : (int * int)) -> (int * int){ _ = (snd p, fst p) } =
  fun p ->
    match p with
    | (x, y) -> (y, x)

let first_pos (p : (int * int){ fst _ > 0 }) : {r:int | r > 0} =
  match p with
  | (x, _) -> x

Contracts as loop invariants demo/lean_fib.ml

Parameter refinements are preconditions, so a recursive function's parameters can carry its invariant — here (a, b) = (fib i, fib (i+1)). Call sites discharge it as ordinary obligations, including at the literal seeds in fib_loop n 0 0 1 and the compound arguments (i + 1), (a + b).

let rec fib_loop
  : (n : int) -> (i : int) -> (a : int{ _ = fib i && i >= 0 })
    -> (b : int{ _ = fib (i + 1) }) -> int{ _ = fib n }
  =
  fun n i a b ->
    if i = n
    then a
    else begin
      fib_loop n (i + 1) b (a + b)
    end

let fib_iter : (n : int) -> int{ _ = fib n } =
  fun n -> fib_loop n 0 0 1

Specs across modules demo/lean_reflectclient.ml

A total_ function's definition is exported in its unit's .cmi. Clients apply it in predicates and prove against it; the .cmi checksum forces re-verification when the definition changes.

let l2 : Reflect_lib.ilist{ Reflect_lib.len _ = 2 } =
  Reflect_lib.Cons (1, Reflect_lib.Cons (2, Reflect_lib.Nil))

let f5 : int{ _ = Reflect_lib.fib 5 } = Reflect_lib.fib 5

Quantifiers demo/lean_quant.ml

forall_/exists_ and implication in predicates; binders are untyped and Lean infers their sorts. Here max2 is not just an upper bound but provably the least one — each branch proves the quantified conclusion under its path fact.

let max2
  : (x : int) -> (y : int)
    -> int{ x <= _ && y <= _ && (forall_ z. x <= z && y <= z -> _ <= z) }
  =
  fun x y -> if x < y then y else x

Correct, not just safe demo/lean_isqrt.ml

Integer square root against a reflected sq: the result is bracketed by squares of the same function the program runs. The midpoint is reflected division; one nonlinear lemma is proved in an embedded block. Nothing in the file is assumed — and returning the wrong endpoint is caught with a concrete counterexample (x = 0).

let total_ sq m = m * m

let isqrt : (x : int{ 0 <= _ }) -> {r:int | 0 <= r && sq r <= x && x < sq (r + 1)} =
  fun x ->
    let rec go
      : (lo : int{ 0 <= _ && sq _ <= x }) ->
        (hi : int{ lo < _ && x < sq _ }) ->
        {r:int | 0 <= r && sq r <= x && x < sq (r + 1)}
      =
      fun lo hi ->
        if lo + 1 < hi
        then begin
          let m = (lo + hi) / 2 in
          if sq m <= x then go m hi else go lo m
        end
        else lo
    in
    go 0 (x + 1)

Mutable locals, loop invariants demo/lean_mutable.ml

Reads of a let mutable variable name its current SSA version; every write mints a fresh one. A [@vox.invariant] formula follows the classical quadruple — asserted at entry, assumed at the loop head, asserted again at the back-edge — and may mention a for-loop's index; after the loop it stands at one past the end.

let iota : (n : int) -> {r:int | (n < 1 && r = 0) || (n >= 1 && r = n)} =
  fun n ->
  let mutable x = 0 in
  (for i = 1 to n do
     x <- x + 1
   done) [@vox.invariant x = i - 1];
  refine_ x

The same search, imperatively demo/lean_imp_binsearch.ml

The recursive bracket invariant of lower_bound, worn as a loop annotation: two unrefined mutable indices, plain reads and writes, and the flip-point postcondition falls out of the invariant together with the negated guard.

let search2
  : (a : int iarray) -> (x : int)
    -> bracket{ _.hi = _.lo + 1
                && -1 <= _.lo && _.hi <= Iarray.length a
                && (0 <= _.lo -> a.(_.lo) < x)
                && (_.hi < Iarray.length a -> a.(_.hi) >= x) }
  =
  fun a x ->
  let n = Iarray.length a in
  let mutable lo = -1 in
  let mutable hi = n in
  (while hi - lo > 1 do
     let l = lo in
     let h = hi in
     let mid = (l + h) / 2 in
     let v = Ia_lib.get a mid in
     if v >= x then hi <- mid else lo <- mid
   done)
  [@vox.invariant
    -1 <= lo && lo < hi && hi <= Iarray.length a
    && (lo = -1 || Iarray.get a lo < x)
    && (hi = Iarray.length a || Iarray.get a hi >= x)];
  let l = lo in
  let h = hi in
  { lo = l; hi = h }

Mutable borrows demo/lean_borrow.ml

RustHorn-style: a borrow hands the continuation a loan whose final value is a prophecy variable p; the borrower proves an export in lender terms, and after resolution the lender reads the residual back with proof. Double use, forged exports, and writes through frozen loans are compile-time errors.

let bump : (a : int) -> int{ _ = a + 1 } =
  fun a ->
  let x = vnew a in
  let p = new_proph () in

    let (r, m1) = mget m in              (* r = now m = x = a *)
    let m2 = mset m1 (r + 1) in
    let _u0 = mdrop m2 in         (* fin m2 = now m2 *)
    (() : unit{ p = a + 1 }))    (* export in lender terms *)
  in
  ignore u;                              (* u carried p = a + 1 *)
  let s = vpeek x' in                    (* s = x' = p *)
  s

A tree flipped in place demo/lean_flip.ml

A mutable tree with a pure ghost model: flip swaps child pointers in place, its dependent signature model _ = mirror (model h) makes each recursive call the induction hypothesis, and flipping twice is provably the identity.

let rec flip : (h : vtree) @ unique -> vtree{ model _ = mirror (model h) } @ unique =
  fun h ->
  let (b, h1) = is_node h in
  if b
  then (
    let (l, k) = take_left h1 in
    let l' = flip l in
    let h2 = put_left k l' in
    let (r, k2) = take_right h2 in
    let r' = flip r in
    let h3 = put_right k2 r' in
    let h4 = swap_kids h3 in
    h4)
  else h1

let roundtrip : (t : tree) -> tree{ _ = t } =
  fun t ->
  let h = of_pure t in
  let h1 = flip h in
  let h2 = flip h1 in
  let r = to_pure h2 in
  r

A separation logic demo/lean_sep.ml

One unique token owns the heap; its refinement carries a reified assertion, and the frame is an explicit parameter. Reads recover the ghost values, writes rewrite the points-to chunks, and two live references are distinct because Star means disjoint.

let swap :
  (r1 : href) -> (r2 : href) -> (a : int) -> (b : int) -> (p : hprop) ->
  htoken{ sat (Star (Pts (r1, a), Star (Pts (r2, b), p))) (hp _) } @ unique ->
  htoken{ sat (Star (Pts (r1, b), Star (Pts (r2, a), p))) (hp _) } @ unique =
  fun r1 r2 a b p t ->
  let f1 = Star (Pts (r2, b), p) in
  let (x, t) = get r1 a f1 t in
  let f2 = Star (Pts (r1, a), p) in
  let (y, t) = get r2 b f2 t in
  let t = set r1 a y f1 t in
  let f3 = Star (Pts (r1, y), p) in
  let t = set r2 b x f3 t in

In-place quicksort over slice borrows, verified against sorted-and-perm: the recursion is a reborrow, and each side's facts come home as prophecy values. Then the same verification runs fork-join — the sub-loans are disjoint by mode, so the sequential proof is the parallel proof.

   checker's, and each task's result is its side's resolution facts.
   The negative probes (bounds, prophecy reuse, forged exports, loan
   escape, racing tasks) live in mechanics/lean_qsort_fail.ml. *)

open Slice_lib

(* Swap two in-bounds positions of a loan: four threaded ops; the
   composed [upd]/[elem] contents expression is re-proved at the
   annotation by congruence alone, and [fin] just threads. *)
let swap :
  (m : slice) @ local unique ->
  (i : int{ 0 <= _ && _ < len (now m) }) ->
  (j : int{ 0 <= _ && _ < len (now m) }) ->
  slice{ now _ = upd (upd (now m) i (elem (now m) j)) j (elem (now m) i)
         && fin _ = fin m }
    @ local unique =
  fun m i j ->
    exclave_
      (let (vi, m1) = sget m i in
       let (vj, m2) = sget m1 j in
       let m3 = sset m2 i vj in
       let m4 = sset m3 j vi in
       m4)

(* Lomuto partition with the pivot parked at the last position.  The
   invariant rides the parameters: positions [0,i) are <= p, the
   window [seg i j] is >= p, the pivot p sits at [n-1], and [j] scans
   until it reaches it.  Each recursive call discharges the halved
   invariant from the path facts and the swap lemmas
   ([swap_le]/[swap_mid]); the final swap parks the pivot at [i], and
   [swap_final_ge] turns the window into the >=-suffix. *)
let rec part :
  (p : int) -> (i : int{ 0 <= _ }) -> (j : int{ i <= _ }) ->
  (s : slice{ j <= len (now _) - 1
              && elem (now _) (len (now _) - 1) = p
              && all_le (take i (now _)) p
              && all_ge (seg i j (now _)) p }) @ local unique ->
  (n : int{ _ = len (now s) }) ->
  (int * slice){ 0 <= fst _ && fst _ < n
                 && elem (now (snd _)) (fst _) = p
                 && all_le (take (fst _) (now (snd _))) p
                 && all_ge (drop (fst _) (now (snd _))) p
                 && perm (now s) (now (snd _))
                 && fin (snd _) = fin s }
    @ local unique =
  fun p i j s n ->
    exclave_
      (if j < n - 1
       then begin
         let (v, s1) = sget s j in
         if v <= p
         then begin
           let s2 = swap s1 i j in
           let q = part p (i + 1) (j + 1) s2 n in
           q
         end
         else begin
           let q = part p i (j + 1) s1 n in
           q
         end
       end
       else begin
         let s' = swap s i j in
         ((i : int), s')
       end)

(* Sequential quicksort on a loan: read the pivot, partition, then
   REBORROW -- the outer split at the pivot index, the inner split
   isolating the pivot's singleton.  Each side is sorted recursively
   and resolved; the singleton is resolved as-is; resolving the inner
   bracket's advanced parent reveals [pv prest] as pivot-then-right.
   Each bracket's export restates its prophecies' facts in the scope
   OUTSIDE the bracket, and the parent loan comes back at
   [app (pv pl) (pv prest)], where the glue lemmas finish. *)
let rec qsort :
  (m : slice) @ local unique ->
  slice{ perm (now m) (now _) && sorted (now _) && fin _ = fin m }
    @ local unique =
  fun m ->
    exclave_
      (let (n, m0) = slen m in
       if n <= 1
       then m0
       else begin
         let (p, mp) = sget m0 (n - 1) in
         let q = part p 0 0 mp n in
         let (k, m2) = q in
         let pl = new_proph () in
         let prest = new_proph () in
         let (mres, u) =
           split pl prest m2 k (fun left rest ->
             let left' = qsort left in
             let _u1 = sdrop left' in
             let pm = new_proph () in
             let pr = new_proph () in
             let (rest_adv, u2) =
               split pm pr rest 1 (fun mid right ->
                 let right' = qsort right in
                 let _u2 = sdrop right' in
                 let _u3 = sdrop mid in
                 (() : unit{ pv pm = take 1 (now rest)
                             && sorted (pv pr)
                             && perm (drop 1 (now rest)) (pv pr) }))
             in
             ignore u2;
             let _u4 = sdrop rest_adv in
             (() : unit{ sorted (pv pl)
                         && perm (take k (now m2)) (pv pl)
                         && sorted (pv prest)
                         && perm (drop k (now m2)) (pv prest) }))
         in
         ignore u;
         mres
       end)

(* Parallel quicksort, same spec: inside the inner bracket both
   sub-loans are live and disjoint, so each once-closure consumes one
   and fork_join2 runs them on separate domains -- each task returns
   its side's resolution facts (global refined units), which survive
   the join; everything else is the sequential proof. *)
let rec psort :
  (m : slice) @ local unique ->
  slice{ perm (now m) (now _) && sorted (now _) && fin _ = fin m }
    @ local unique =
  fun m ->
    exclave_
      (let (n, m0) = slen m in
       if n <= 1
       then m0
       else begin
         let (p, mp) = sget m0 (n - 1) in
         let q = part p 0 0 mp n in
         let (k, m2) = q in
         let pl = new_proph () in
         let prest = new_proph () in
         let (mres, u) =
           split pl prest m2 k (fun left rest ->
             let pm = new_proph () in
             let pr = new_proph () in
             let (rest_adv, u2) =
               split pm pr rest 1 (fun mid right ->
                 let (ul, ur) =
                   Par_lib.fork_join2
                     (fun () ->
                       let left' = psort left in
                       let _u = sdrop left' in
                       (() : unit{ sorted (pv pl)
                                   && perm (take k (now m2)) (pv pl) }))
                     (fun () ->
                       let right' = psort right in
                       let _u = sdrop right' in
                       (() : unit{ sorted (pv pr)
                                   && perm (drop 1 (now rest)) (pv pr) }))
                 in
                 ignore ul;
                 ignore ur;

Reflected arithmetic Vox_reflect

+ - * / mod, comparisons, and && || not carry their logical meaning, recognized by primitive rather than by name (a shadowed (+) is not addition). Division is OCaml's T-division, totalized soundly under partial correctness. A branch condition contributes itself as a fact: writing if n <= 0 is enough.

A verified module behind an interface

The shape that scales. bst.mli states the model — whole-tree membership, the ordering invariant, a model-level insert — and proves its theorems once, in the interface's embedded block; definitions and theorems travel in the .cmi. The implementation is checked against them arm by arm: the efficient one-path search is proved equal to membership over the whole tree (the ordering lemmas account for the subtrees the code never visits), and each insert arm is proved to build exactly the model's tree. Nothing is assumed, and no verification keyword appears in the code.

type tree =
  | Leaf
  | Node of tree * int * tree

@[grind] def mem : Int -> Vox_Bst_tree -> Prop
  | _, .Leaf => False
  | x, .Node l v r => x = v ∨ mem x l ∨ mem x r

@[grind] def all_lt : Vox_Bst_tree -> Int -> Prop
  | .Leaf, _ => True
  | .Node l v r, b => v < b ∧ all_lt l b ∧ all_lt r b

@[grind] def all_gt : Vox_Bst_tree -> Int -> Prop
  | .Leaf, _ => True
  | .Node l v r, b => v > b ∧ all_gt l b ∧ all_gt r b

@[grind] def bst : Vox_Bst_tree -> Prop
  | .Leaf => True
  | .Node l v r => all_lt l v ∧ all_gt r v ∧ bst l ∧ bst r

@[grind] def insert : Int -> Vox_Bst_tree -> Vox_Bst_tree
  | x, .Leaf => .Node .Leaf x .Leaf
  | x, .Node l v r =>
      if x = v then .Node l v r
      else if x < v then .Node (insert x l) v r
      else .Node l v (insert x r)

   contracts through the abbreviation like any other. *)

   (which quantifies the WHOLE tree): the ordering lemmas bridge the
   path the code takes to the subtrees it skips. *)

Trust model

ConstructStatusNotes
refine_ eProved Emitted as a Lean theorem; failure is a compile error with goal, hypotheses, and model.
parameter contractsProved Discharged at every application, at the argument's logical name.
total_ definitionsDefinitional The emitted Lean def is the OCaml body; Lean independently checks termination.
assume_ eRuntime-checked The compiler inserts the test; a violated assumption raises rather than entering the logic. Compiled only when the check is faithful to the logic; otherwise a compile error.
assume_unchecked_ e, [%%vox.lean] blocksTrusted The explicit trust surface. In the fib development it amounts to one line: floor halving.

Known limits, by design: partial correctness (a diverging call neither proves nor asserts anything), and ideal integer arithmetic (overflow is outside the model). Both are documented in DESIGN.md.
